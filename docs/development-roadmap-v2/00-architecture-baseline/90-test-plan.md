# 阶段00测试计划

## 执行前说明

阶段 00 尚未建设 Schema 工具链和 CI，因此本阶段的自动检查以 Markdown、链接和静态矩阵核对为准。OpenAPI、AsyncAPI 与 JSON Schema 的机器语法、生成和兼容性检查属于阶段 01；本阶段必须确认其规则已在[共享语义基线](./07-shared-semantics-contract-baseline.md)中定义。

## 自动与静态检查

| 编号 | 检查 | 执行方式 | 通过标准 |
|---|---|---|---|
| T00-01 | 文档格式 | `git diff --check` | 无空白字符错误 |
| T00-02 | 相对链接 | 扫描 Markdown 链接并逐一解析 | 阶段 00 和 ADR 链接均存在 |
| T00-03 | 服务 Owner | 对照服务目录，按 Aggregate 去重 | 每项事实恰好一个 Owner |
| T00-04 | 依赖无环 | 根据通信基线绘制有向图并做人工拓扑排序 | 无同步或事件回写环 |
| T00-05 | 平台越权 | 审查平台服务的禁止写入列 | 无领域事实写权限 |
| T00-06 | 契约字段 | 核对命令、事件和错误信封 | 必填字段、版本和关联 ID 齐全 |
| T00-07 | ADR 门禁 | 审查 ADR 状态和阻塞说明 | 阶段 01 硬门禁均 ACCEPTED |

## 场景测试

| 编号 | 场景 | 操作 | 预期结果 |
|---|---|---|---|
| T00-08 | Agent 越权 | 让 Agent 请求修改 `PortfolioSnapshot` | 服务目录定位为禁止写入，必须经 Owner 的受控命令 |
| T00-09 | 即时风控 | Governance 需得到硬风控结论 | 选择鉴权 REST 命令；不能只发布事件 |
| T00-10 | PIT 回放 | 在时点 T 查询 `availableAt > T` 的 Outcome | 拒绝读取并记录未来数据泄漏原因 |
| T00-11 | 大对象事件 | 发布大型回测结果 | Payload 仅有 Artifact URI/Hash，不含矩阵或二进制 |
| T00-12 | 重复命令 | 同一幂等键重复提交写命令 | 返回首次处理结果，不产生第二次副作用 |
| T00-13 | 破坏性变更 | 删除或收紧事件字段 | 要求新 Subject Major 与迁移期 |

## 证据与结论

每项测试记录执行人、日期、输入文档版本、命令或审查路径、PASS/FAIL、问题编号和修复证据。所有检查 PASS 且人工场景没有未解决 P0/P1 才可进入 `99-acceptance.md`；T00-07 失败时阶段结论必须为 FAIL。
