# 02-04 生产强化与运维

## 实施步骤

1. 为每个供应商配置限流、超时、退避、熔断和数据许可元数据。
2. 实现增量同步、断点续传、校验后补发和来源切换；切换来源必须产生新DataVersion。
3. 指标覆盖同步延迟、缺失率、质量FAIL、最新可用交易日、Outbox Lag和Artifact失败。
4. 建立数据回补、版本回滚、原始Artifact重放和灾难恢复Runbook。
5. 定义日线、分钟线、财务数据的SLO与新鲜度阈值。

首版供应商职责、字段合并顺序及PIT补全要求以[02-05首版数据源与PIT补全策略](./05-v1-data-source-policy.md)为准。实现时必须把来源策略作为版本化配置保存，禁止把“主来源优先”或差异阈值散落为代码常量。

## 故障测试

- 429、超时、半包、字段变更和部分日期缺失。
- 主来源故障时不得将不完整数据标为READY。
- 数据库/MinIO/NATS单点故障恢复。
- 大范围历史回补不阻塞最新日常发布。
- 浮动`latest`、Release Manifest不匹配、来源间字段冲突和更正公告晚到。
- 补充源不可用时不得伪造完整覆盖；受影响的价值/质量能力必须显式降级。

## 完成条件

Runbook可由另一名开发者恢复指定DataVersion，并得到相同contentHash；验收证据包含来源Release、原始Artifact Hash、来源策略版本、许可引用和对账报告。
