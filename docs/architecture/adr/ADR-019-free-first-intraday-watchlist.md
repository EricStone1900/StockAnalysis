# ADR-019：免费优先的准实时 Watchlist 行情

- 状态：ACCEPTED
- 生效日期：2026-08-31
- 决策人：项目负责人
- 影响阶段：06、09、10、12

## 背景

日频策略只在收盘后生成候选组合。交易时段需要以较低成本监控持仓、待执行证券和当日候选股的明显异常，但首版不要求 Tick 级或逐笔级行情。

免费数据接口可能限流、变更或不可用，且不提供生产 SLA。系统不能把“每10分钟拉取一次”误解释为每10分钟生成建议或交易，也不能因行情陈旧而产生“市场正常”的伪结论。日频 Alpha 的因子、模型和回测不包含盘中择股逻辑，盘中层不能把普通分钟波动解释为新的 Alpha。

## 决策

1. 阶段06首版采用版本化`MonitorPolicy`的`FREE_TIERED_10_20_30`运行档：交易时段每10分钟获取一次批量行情快照，在本地过滤、标准化和聚合 Watchlist；禁止对每只股票发起独立请求。
2. 同一批量快照只请求一次并服务所有到期层级：P0（持仓、待执行证券）每10分钟评估，P1（当日量化候选股）每20分钟评估，P2（普通人工关注股）每30分钟评估。P1/P2复用10分钟快照，不得为各层额外请求上游数据。
3. 默认活跃 Watchlist 上限为50支，稳定性验收后可配置扩展至80支；100支只作为容量、降级和恢复压力门槛，不是首版常态配置。
4. `MonitorPolicy`必须记录`policyVersion`、各层间隔（首版只允许10/20/30分钟）、阈值、冷却、升级/降级规则和生效时间。策略在交易时段冻结；人工或系统变更默认下一个交易时段生效，紧急安全策略变更必须审计。
5. 阈值越过后的盘中动作只允许`HOLD`、`WATCH`、`DELAY`、`CANCEL`、`INTRADAY_RISK_REDUCTION`和`EXECUTION_CORRECTION`。`DELAY/CANCEL`只影响尚未接受的日频目标批次；第二批仍受ADR-010约束，默认仅风险减仓或执行修正。不得因普通盘中阈值新增日频 Alpha 买入或重新排序目标组合。
6. 初期可使用经许可评估的免费批量 Adapter 作为研究和 Shadow 的首选，例如 AKShare 对全市场快照的封装。必须保存实际底层来源、Adapter/Schema版本、许可范围、请求/响应时间和原始证据引用。
7. 免费源只提供`best effort`准实时能力，不能承诺生产级实时 SLA 或作为自动交易的唯一行情事实。ADR-001和ADR-007仍负责未来合规主/备用生产行情供应商与 Gateway 的最终选型。
8. 单个批次在计划时刻后120秒内未完成、活跃 Watchlist 覆盖不足、`quoteAgeSeconds`超过180秒、字段校验失败或连续两轮拉取失败时，数据质量为`WARN`或`FAIL`；Worker必须告警，禁止发布“正常”异常检测结论，禁止触发基于该批数据的风险放行或新调仓。
9. 备用 Adapter 只能通过同一`MarketGateway`契约接入。切换时必须记录`sourceChange`、Schema/字段映射版本和质量状态；不同来源的数据不得静默混合为同一窗口。
10. P0持仓和待执行证券在获得经验证的推送/付费或券商只读 Gateway 后，才可配置为1～5分钟；在免费首版中仍遵循10分钟批量档，不以高频逐股轮询规避上游限制。

## 容量与验收口径

A股常规交易日约24个十分钟窗口。100支股票对应约2400个股票窗口观测/日；50和80支分别约1200和1920个。该规模的本地过滤、窗口计算和存储不是容量瓶颈，验收重点是上游成功率、数据新鲜度、覆盖率、恢复行为和事件正确性。

- 50支常态连续20个交易日：有效窗口成功率不低于98%，不允许连续两轮未恢复的失败；统计必须排除午休和非交易时段。
- 80支常态：达到与50支相同门槛后才可启用。
- 100支压力：验证P95端到端窗口完成时间不超过120秒、故障降级和恢复正确；未通过不得降低50/80支门槛。

`有效窗口`要求活跃 Watchlist 全量可解析、数据新鲜度合格且无未解决的来源切换冲突。免费源本身不可用时，输出受控降级并不计为成功，不能以缓存旧行情伪造成功。

## 后果与回滚

- 优点：以极低请求频率覆盖全部目标股票，避免100个独立请求在窗口边界形成突发；50支起步为上游波动保留余量。
- 代价：首版是10分钟采样、10/20/30分钟分层评估的准实时监控而非严格实时；免费源故障会降低监控覆盖，不能保证连续可用。
- 回滚：数据源、字段或SLO不满足时，将运行档降回50支或停止盘中监控，仅保留日频策略；不得为了维持功能绕过质量门禁或切换到未批准来源。
